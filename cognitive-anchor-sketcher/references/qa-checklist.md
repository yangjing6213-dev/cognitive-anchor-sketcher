# QA Checklist

## 生成前对话 QA

生成、改图或批量生成前，先读取 `qa-dialogue-workflow.md` 并逐项确认：

- `article_direction` 已由用户明确确认。
- `style_profile` 已确认；推荐值或默认值没有被当作沉默同意。
- `ip_profile` 已确认；显式未知 profile 已阻塞。
- 自定义 IP 已有参考图、已确认草稿和授权范围，且 `authorization_status = user_authorized`。
- shot list、输出规格和生成模式已确认。
- 已向用户展示最终摘要并得到“生成全部”或“生成第一张试稿”的明确选择。
- 当前 `qa_state = GENERATION_READY`；否则不得调用生图工具。
- 已读取 `codex-cli-generation.md` 并选择唯一合法路径：当前 Codex CLI 会话直接调用，或明确的非 CLI 宿主在预检后单次桥接。
- 未请求、读取、打印或使用 API 密钥；未安排 Images API、`image_gen.py`、SDK、其他提供商或递归 Codex 回退。

## 使用上下文

- 先核对本次已解析的 `style_profile` 与 `ip_profile`；未指定时分别使用 `minimal-line` 与 `xiaohei`。
- QA 只检查当前所选画风和 IP；显式指定但无法解析的档案或画风必须先阻塞，不得静默替换。

## 生成执行与文件 QA

- 只接受内置工具实际返回的原始输出路径；没有扫描目录、按时间猜测或自行推导文件名。
- 返回路径明确存在并指向普通文件；否则已按 `codex-cli-generation.md` 硬停止，未进入视觉 QA。
- 原始文件仍在返回位置，未被移动、修改、删除或覆盖。
- 内部 QA 与用户预览使用该原始文件；只有用户接受后才复制到 `assets/<article-slug>-illustrations/`。
- 目标名已确认未占用；冲突时使用新的 `-v2`、`-v3` 版本名，没有覆盖已有资产。
- CLI、ChatGPT 认证、内置工具、调用、返回路径或复制任一失败时，没有自动重试、换后端或声称成功。

## 公共必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有当前所选 IP。
- 当前所选 IP 承担核心动作，不只是装饰；未指定 IP 时这里的“当前所选 IP”就是小黑。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。

### `minimal-line` 分支

- 继续遵守 `style-dna.md` 的细黑手绘线稿、留白和冷静怪诞基线。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

### `emotion-doodle` 分支

- 黑色是角色、轮廓和主要动作的主色。
- 黄色/橙色/蓝色只少量出现并有明确语义。
- 洋红没有成为画面主色。
- 有粗黑手绘线、动作/情绪涂鸦，但不是商业 3D 渲染或表情包海报。

## 自定义 IP 来源与授权分支

- 只有用户确认或修改后的 `ip-profiles/<slug>/profile.md` 才能进入生成；确认前的 `draft_unconfirmed` 只能讨论，不能生成。
- 每个自定义档案都存在匹配的 `ip-profiles/<slug>/provenance.md`，并记录非识别性来源说明、参考模式、确认时间、确认状态和授权状态；可获得时还记录 `sha256`。
- `reference_mode`/`authorization_status` 必须明确为 `analysis_only` 或 `user_authorized`；`missing`、`unknown` 或其他不明确状态一律阻塞。
- `analysis_only` 仅允许分析和提炼抽象特征，不得据此生成、临摹、抠取、拼贴或直接嵌入参考图；`user_authorized` 也只能在用户确认的范围内使用。
- 不得把上传/引用本身当作授权，也不得在来源状态缺失时声称已获商用许可。

## 失败信号

出现以下情况，记录为不合格；只有用户明确选择并再次确认后，才重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 当前所选 IP 像吉祥物、表情包或可爱卡通。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和可选历史示例素材里的旧案例构图过于相似。

## 迭代方法

- 太普通：让当前所选 IP 成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、blank serious expression、not cute、not mascot。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和当前所选 IP 的动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。

## 用户最终验收

内部 QA 通过不等于用户验收通过。展示图片与简短检查结果后，提供：

1. 接受全部图片（推荐）
2. 指定图片重新生成
3. 只修改中文批注、留白或构图
4. 返回修改画风或 IP
5. 保留当前版本并结束

只有用户选择 1 或 5，才进入交付；选择 2–4 时按 `qa-dialogue-workflow.md` 回退。不要在未获选择时自动重生成，也不要覆盖现有资产。
